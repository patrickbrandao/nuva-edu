# 027 — Servidor MCP da administração

Status: aprovada
Depende de: 001, 003, 008, 028

## Contexto

O admin e o gerente querem operar a escola por agentes de IA (consultar alunos, conceder acesso, cadastrar conteúdo, responder chamados). O servidor MCP expõe a API administrativa como ferramentas, autenticadas por chaves que o próprio usuário emite e revoga. A chave não tem poderes próprios: ela age como o usuário que a emitiu.

## Requisitos

- RF-01: A `admin-api` serve MCP por Streamable HTTP em `https://<NUVA_ADMIN_HOST>/mcp`, no mesmo processo da API.
- RF-02: Só usuários com papel `admin` ou `manager` emitem chaves. `instructor` e `student` não emitem.
- RF-03: Um usuário pode ter várias chaves ativas ao mesmo tempo, cada uma com nome obrigatório e validade opcional.
- RF-04: O valor da chave é exibido uma única vez, na emissão. O banco guarda apenas o hash.
- RF-05: O emissor revoga as próprias chaves; o `admin` revoga a chave de qualquer usuário. A revogação vale na requisição seguinte.
- RF-06: A cada chamada, as permissões são as do papel ATUAL do emissor. Rebaixar, suspender ou excluir o emissor afeta todas as chaves dele imediatamente.
- RF-07: As ferramentas espelham a API administrativa e chamam as mesmas funções de `packages/core`; não existe regra de negócio exclusiva do MCP.
- RF-08: Nenhuma ferramenta, recurso ou mensagem de erro do MCP devolve a senha de um usuário, o hash ou o valor de uma chave, tokens de sessão ou segredos de integração.
- RF-09: Toda chamada de ferramenta é registrada na auditoria ([028](028-auditoria.md)) com a chave usada.
- RF-10: A listagem de ferramentas (`tools/list`) mostra apenas o que o papel atual do emissor pode executar.
- RNF-01: Limite de 120 chamadas por minuto por chave (ajustável por `NUVA_MCP_RATE_PER_MIN`); acima disso, erro com tempo de espera.
- RNF-02: No máximo 20 chaves ativas por usuário (ajustável por `NUVA_MCP_MAX_KEYS`).
- RNF-03: Resultados de listagem paginados com no máximo 100 itens por página.
- RNF-04: A verificação da chave acrescenta no máximo 10 ms (p95) à chamada.

## Comportamento

### Chaves

- Formato: `nuva_mcp_` + 40 caracteres aleatórios (base62, gerados com fonte criptográfica). Os 8 primeiros caracteres após o prefixo formam o `key_prefix`, guardado em claro para identificar a chave na interface.
- O hash guardado é SHA-256 do valor completo. A chave tem entropia alta, então não precisa de função lenta.
- Emissão: tela "Chaves MCP" no site admin (e `POST /api/v1/mcp-keys`). Campos: `name` (1 a 60 caracteres), `expires_at` (opcional). A resposta traz o valor completo; nenhuma outra rota o devolve.
- Listagem: nome, `key_prefix`, criada em, expira em, último uso (data e IP), estado (`active`, `expired`, `revoked`).
- Revogação: marca `revoked_at`; a chave continua na lista como histórico.
- Expiração: chave com `expires_at` no passado é recusada; não é apagada.

### Autenticação de uma chamada

1. O cliente envia `Authorization: Bearer <chave>`.
2. A `admin-api` calcula o hash, busca em `mcp_keys` e recusa com 401 se não existir, estiver revogada ou expirada.
3. Carrega o emissor. Recusa com 403 se estiver suspenso (qualquer tipo), excluído ou com papel diferente de `admin` e `manager`. Rebaixar o emissor para `student` ou `instructor` marca as chaves dele como revogadas; rebaixar de `admin` para `manager` mantém as chaves, agora com os poderes de `manager` ([008](008-papeis-e-permissoes.md)).
4. Monta o contexto de autorização com o papel atual do emissor e segue para a ferramenta.
5. Atualiza `last_used_at` e `last_used_ip` (no máximo uma escrita por minuto por chave).

Sessões do Streamable HTTP não guardam autorização: cada requisição repete os passos 1 a 4.

### Catálogo de ferramentas

Nomes em inglês, no formato `dominio_acao`. "Papel mínimo" segue a matriz de [008](008-papeis-e-permissoes.md); `manager` inclui tudo o que não está marcado como só `admin`.

| Domínio | Ferramentas | Papel mínimo |
| --- | --- | --- |
| Usuários | `users_list`, `users_get`, `users_suspend`, `users_unsuspend` | `manager` |
| Usuários | `users_set_role`, `users_delete` | `admin` |
| Catálogo | `courses_list`, `courses_get`, `courses_create`, `courses_update`, `modules_create`, `modules_update`, `lessons_create`, `lessons_update`, `lessons_reorder`, `ebooks_list`, `ebooks_create`, `ebooks_update`, `bundles_list`, `bundles_create`, `bundles_update` | `manager` |
| Catálogo | `products_set_price`, `products_delete` | `admin` |
| Acessos | `entitlements_list`, `entitlements_grant`, `entitlements_revoke` | `manager` |
| Vendas | `orders_list`, `orders_get`, `subscriptions_list`, `sales_summary` | `manager` |
| Vendas | `orders_refund`, `plans_create`, `plans_update`, `coupons_create`, `coupons_update` | `admin` |
| Fórum | `forum_topics_list`, `forum_posts_list`, `forum_post_hide`, `forum_topic_close`, `forum_topic_pin`, `forum_categories_create` | `manager` |
| Moderação | `reports_list`, `reports_resolve`, `cases_hide` | `manager` |
| Chamados | `tickets_list`, `tickets_get`, `tickets_reply`, `tickets_set_status` | `manager` |
| Eventos e novidades | `events_list`, `events_create`, `events_update`, `announcements_create`, `announcements_update` | `manager` |
| Gamificação | `badges_award` | `manager` |
| Gamificação (ajuste de pontos) | `points_adjust` | `admin` |
| Operação | `jobs_failed_list`, `webhooks_failed_list`, `audit_search` | `admin` |
| Configuração | `settings_get`, `settings_update` | `admin` |

Regras do catálogo:

- Ferramentas de leitura declaram `readOnlyHint`; as que apagam ou reembolsam declaram `destructiveHint`.
- Não existem ferramentas para: ver senha, emitir ou listar chaves MCP, criar outro `admin`, alterar integrações (segredos de pagamento, login social, SMTP). Essas ações só existem no painel.
- `users_get` e `users_list` devolvem o mesmo conjunto de campos da API, sem `password`.
- Erro de permissão devolve erro de ferramenta com o texto "permissão insuficiente para o papel atual", sem revelar a existência do recurso.

## Interfaces e contratos

- Transporte: MCP Streamable HTTP em `POST /mcp` e `GET /mcp`, roteado pelo Traefik para a `admin-api`.
- Gestão de chaves em `apps/admin-api/openapi.yaml`: `GET /api/v1/mcp-keys`, `POST /api/v1/mcp-keys`, `DELETE /api/v1/mcp-keys/{id}`; para o `admin`, `GET /api/v1/users/{id}/mcp-keys`.
- A lista de ferramentas, com esquema de entrada e saída de cada uma, é gerada em `docs/` a partir do código do servidor MCP; esta spec é a referência de quais existem e de quem pode usá-las.

## Dados

Tabela `mcp_keys`, de propriedade da `admin-api`:

| Campo | Descrição |
| --- | --- |
| `id` | UUID v7 |
| `user_id` | Emissor |
| `name` | Nome dado pelo emissor |
| `key_prefix` | 8 caracteres em claro |
| `key_hash` | SHA-256 do valor completo, único |
| `created_at`, `expires_at`, `revoked_at` | Ciclo de vida |
| `revoked_by` | Quem revogou |
| `last_used_at`, `last_used_ip` | Último uso |

Retenção: chaves revogadas ou expiradas ficam 2 anos, junto com a auditoria, e depois são apagadas pelo expurgo diário.

## Critérios de aceite

- [ ] Chave emitida por `manager` lista apenas ferramentas de `manager`; `orders_refund` não aparece e, se chamada, é recusada.
- [ ] O valor da chave aparece só na resposta da emissão; nenhuma consulta posterior o devolve e o banco só tem o hash.
- [ ] Rebaixar o emissor de `admin` para `manager` faz a chamada seguinte a `settings_update` falhar, sem reemitir a chave.
- [ ] Suspender o emissor faz todas as chaves dele devolverem 403 na chamada seguinte.
- [ ] Chave revogada ou expirada devolve 401.
- [ ] Nenhuma resposta de ferramenta contém o campo `password` (teste percorre todas as ferramentas de usuário).
- [ ] Cada chamada gera um registro em `audit_log` com `mcp_key_id`.
- [ ] A 121ª chamada no mesmo minuto é recusada com indicação de espera.

## Fora de escopo

- Escopos por chave (a chave sempre herda o papel inteiro do emissor).
- MCP no classroom ou para alunos e instrutores.
- Transporte stdio e SSE legado.
- OAuth para clientes MCP.
